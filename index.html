How this site is built

This page is its own case study: no UI framework, typed content, and a pipeline that checks quality before anything goes live.

From content to live site

  1. 01 · content Typed JSON projects, career, skills and IT domains, checked against TypeScript types
  2. 02 · code TypeScript modules one small module per section; Canvas, CSS 3D and GSAP for motion
  3. 03 · build Vite code split per section, hashed files, self-hosted fonts
  4. 04 · gate GitHub Actions types, lint, formatting and a Lighthouse budget must pass
  5. 05 · live GitHub Pages deployed only when every check is green

content updates A private /admin/ page edits projects in the browser, converts images to WebP, and publishes through the GitHub API as one atomic commit, which runs the same pipeline.

  • Content is data

    Every project, role and skill lives in JSON with a TypeScript contract, so adding work never means touching layout code.

  • Load what's needed

    The first screen ships a few kilobytes; each section below loads its own code just before it scrolls into view.

  • Motion with manners

    Every effect pauses off screen and respects reduced-motion settings; the carousel has a pause button.

  • Accessible by default

    Native dialogs, WAI-ARIA tabs and carousel patterns, visible focus, and 4.5:1 contrast in both themes.
